# List of features that are either a screen or a component

> Key features to highlight in digitizing the Cavite Tourism Passport. This is not the complete list of screens and components in the app. Platform: Android only.
> Feature numbers come from the master feature list (Features.docx), so gaps in numbering are intentional. Features 19 (reset) and 21 are out of scope for this project (see "Out of Scope" below). #22 Settings (which hosts #16, #17, and #18) and #23 Event Information Panel were added during review. #7 Manual Stamp Request was first out of scope and was later added to the app as a photo request reviewed by admins.
>
> Implementation status (2026-11-22): every MVP feature runs on the live Supabase backend except sending push notifications from the server (#17 and #20: the app registers for notifications and opens tapped ones, but nothing sends them automatically yet) and contact number verification in #2 (waiting for an SMS provider). Details: `supabase/INTEGRATION-STATUS.md` on the developer's machine.

**Type legend:** `screen` = full page, `component` = reusable UI element, `indicator` = small status display, `rule/logic` = behavior or business rule with no dedicated UI, `system behavior` = background behavior (e.g. notifications)

**Priority legend:** `MVP` = needed for the first release, `Later` = can follow after launch (suggested, adjust as needed)

| Feature No. | Feature | Type | Location | Description | Dependencies | Priority |
| ----------- | ------- | ---- | -------- | ----------- | ------------ | -------- |
| 1 | Registration and Login | screen | Shown on first launch or when signed out | Contains the login and sign up screens. Sign up is a multi-step flow: enter the email, enter the verification code received by email, then enter the details (first name, last name, address, and password). The login screen has a "Forgot password" button, which also requires email verification before the password can be reset. Both screens also offer "Continue with Google": a new Google account skips the email and code steps and only enters first name, last name, and address (no password; the name is prefilled from Google, and the terms must be accepted). A Google account with the same email as an existing account signs in to that same passport. | None | MVP |
| 2 | Account and Passport ID | screen | Account tab | Contains the account details of the user: name, address, email, and Passport ID. The contact number is not collected at sign up. The user can add it later in the account details, which requires an additional verification step. The digital passport that shows the collected stamps is a separate screen (see #8). | 1 | MVP |
| 3 | Information Panel | screen | Opened from Explore (#4) or an itinerary (#12) | Contains the necessary information about a site/destination: basic description, category (Dining, Staycation, Adventure, Heritage, or Festival), address, operating hours, photos, visited/unvisited indicator, and the location with an "Open Maps" button. It has no scan button, since scanning is done with the center tab bar button (#5). Contact details are intentionally not included. | 4, 13 | MVP |
| 4 | Partner Directory | screen | First tab in the tab bar, labeled "Explore" | Has a segmented toggle at the top with two views: **Sites** and **Itineraries** (see #12). The Sites view contains the list of partner sites/destinations with a **search bar** and category filters (Dining, Staycation, Adventure, Heritage). **Search shows the address of each site. Contact details are intentionally NOT included.** Also contains the Interactive Map (#13) as a map view. | 3, 12, 13 | MVP |
| 5 | QR Stamp Scanning | component | Center of the tab bar, alongside the tab/screen buttons | A button that opens the app's QR scanner. Scanning collects a stamp, and the partner name, date, and time are recorded automatically (the time is the moment the record is created). The stamp then appears in the Digital Passport (#8). Shows an "Invalid QR code" modal for unrecognized codes and an "Already scanned" modal for sites already stamped in the current promo period. Requires an internet connection; without one, scanning is unavailable. Before the scanner screen is displayed, the app asks the user for location and camera permissions. If the user declines, the scanner screen cannot be accessed. | 1, 3, 6 | MVP |
| 6 | GPS Check-in (QR Location Verification) | rule/logic | Runs when a QR code is scanned (#5) | Checks that the user is physically at the site's location when scanning its QR code. A stamp is awarded only if the verification succeeds. If the user is not at the location or verification fails, the app shows a failed scan result with an appropriate error message. | 3 (site coordinates), 5 | MVP |
| 7 | Manual Stamp Request (stamp requests) | screen | A card below the passport on the Passport screen (#8), the Account tab, a site's information panel (#3), and the scanner (#5) | For stamps in the user's physical passport, e.g. at sites without a QR station. The user picks the site and the visit date (within the current promo period), attaches a photo of the stamp (JPEG, PNG or WebP, up to 5 MB) and an optional note, and sends it for review. One request per site can wait for review at a time, and a site already stamped this period can't be requested. Admins approve it (the stamp and its points are added to the digital passport) or reject it with a reason, which the user sees on the Passport screen with a "Submit again" option. Pending requests show as "Pending review" slots in the passport. Reviewing happens in the admin dashboard (until it exists, in the Supabase SQL editor). | 3, 8, 19, admin dashboard | MVP |
| 8 | Digital Passport (Stamp Book) | screen | Own button in the tab bar | A screen styled like a passport. At the top, a summary card shows the stamps collected (for example 4 of 20), the points balance, an overall completion bar, and an "Active Season" badge. Below it, a segmented toggle switches the passport card between two views: **Identity Page** (the user's passport details, with a generic person icon in the holder slot, the same for every user) and **Visas & Stamps** (the stamps the user has unlocked by scanning QR codes, grouped by category, with uncollected slots shown as outlines). Each stamp shows the partner name, municipality, date, and points. A "View Rewards" button sits below the card. Follows the generated Stitch design (design/screens/05-passport), not a page-turn booklet. | 2, 3, 5 | MVP |
| 9 | Points | rule/logic | None (no dedicated UI; the total is shown in Progress Tracking #10) | Points are awarded per stamp collected: Dining = 150, Staycation = 200, Adventure = 100, Heritage = 50, Festival = 50. Festival stamps give bonus points only and do not replace the stamp requirement from the four main categories (Dining, Staycation, Adventure, Heritage). Festival stamps are only available while the festival is active, since some festivals are not held every year. Each site can earn points only once per promo period; repeat visits earn no points. | 3 (category field), 19 | MVP |
| 10 | Progress Tracking | component | App header (under the user name) and the Rewards screen (#11) | The header shows the user's total points as "[n] pts", and tapping it opens the Rewards screen. In the Rewards screen, each reward shows what the user still needs to unlock it: which of the four main categories still need a stamp, and how many more points are required. Collected stamps are shown in the Digital Passport (#8). | 5, 9 | MVP |
| 11 | Reward Redemption | screen/component | Rewards screen, opened by tapping the points in the header or the "View rewards" button below the passport on the Passport screen | Consists of a **Rewards list screen** and a **Reward detail screen**. To be eligible for any reward, the user needs at least one stamp from each of the four main categories (Dining, Staycation, Adventure, Heritage) and at least 700 points. Individual rewards may cost more than 700 points. Once eligible, the user can optionally generate a single-use claim QR code that tourism office officers scan to claim the prize. Generating it is optional, and users can keep collecting points toward a higher reward. Points are deducted when a reward is claimed. Each person can claim only one prize per promo period. Limited rewards have participant limits; once fully claimed, the app shows that the reward is no longer available. Reward availability is managed by the Tourism Office through the admin webpage. Officer-side scanning is handled by a separate tool. | 2, 9, 10, 19, officer verification tool | MVP |
| 12 | Suggested Itineraries | screen/component | "Itineraries" view of the Explore tab (#4), switched with the segmented toggle at the top | Four fixed itineraries shown as full-size cards (tour type, number of stops, and stamp progress): Day Tour A, Day Tour B, Overnight Tour A, and Overnight Tour B. Tapping a card opens its detail screen. Each has ordered stops, a route shown on the map, and stops that are checked off automatically as the user collects each stamp. | 3, 4, 5, 13 | Later |
| 13 | Interactive Map | component | Explore (#4) map view, itinerary routes (#12), and Cavite Province and Expressway Info (#15) | Interactive map that shows the location of the selected destination, or the group of destinations and route of an itinerary. In Cavite Province and Expressway Info, it shows pins for partner establishments, heritage sites, and each town's signature food or product, plus the expressways. | 3, 4 | MVP |
| 14 | Events Calendar | screen | Discover tab in the tab bar ("Events" view of the segmented toggle at the top) | Features the current and upcoming festivals and events of the province in a scrollable list. Tapping an event opens its Event Information Panel (#23). Reminders for festivals are sent as notifications through Push Notifications (#17). | None | Later |
| 15 | Cavite Province and Expressway Info | screen | "About Cavite" view of the Discover tab (#14), switched with the segmented toggle at the top | Contains three paragraph sections: Historical and Topographical Riches, Culinary Delights, and Cultural Immersions. Followed by a list of the province's festivals (tapping one opens its Event Information Panel, #23), then an interactive map of Cavite (#13) with pins for partner establishments, heritage sites, and each town's signature food or product, which also shows the expressways in the province (CAVITEX, CAVITEX C5 Link, and CALAX) with information about each one and the location span it covers. | 13, 14 | Later |
| 16 | FAQs and Help | component | Settings screen (#22) | Contains FAQs and help. | 22 | Later |
| 17 | Push Notifications | component | Settings screen (#22) | Toggle button to allow the app to send notifications to the user. Turning it off disables all notifications. Notifications cover new partner establishments, festivals (including festival reminders), rewards availability, and promo-end reminders (#20). | 22 | MVP |
| 18 | Social Links | component | Settings screen (#22) | Shortcuts to the official pages of Biyaheng South, Cavite Tourism, DOT IV-A, and DILG IV-A. | 22 | Later |
| 19 | Promo Period | indicator | Anywhere appropriate in the app (shown on Explore and Passport) | Shows the current active period during which the user can collect points. The period is designated by the Tourism Office through the admin webpage, not hardcoded in the app. Resetting the period is handled by the admin panel (see Out of Scope). | Admin dashboard | MVP |
| 20 | Promo-End Reminders | system behavior | Delivered as push notifications | Notifications sent before the promo ends, encouraging the user to collect additional stamps or redeem eligible rewards before the deadline. Timing is based on the promo end date set in the admin webpage. | 17, 19 | MVP |
| 22 | Settings | screen | Gear icon on the Account screen (#2) | Hosts an Account section (edit first and last name and city/municipality, change password with the current password or an emailed code, add/verify the contact number until it is verified, and delete the account after confirming with the password), FAQs and Help (#16), Push Notifications (#17), and Social Links (#18). Accounts made with Google that have no password set one through the emailed code, and confirm account deletion by choosing their Google account again instead of typing a password. | None | MVP |
| 23 | Event Information Panel | screen | Opened from the Events view (#14) or the festival list in About Cavite (#15) | Contains the necessary information about an event or festival: name, photos, date and time, a "Happening now" or "Upcoming" label, the address with an "Open Maps" button, and a description. For festivals that offer a stamp, it also shows the bonus points available. It has no reminder button (reminders are push notifications, #17), no scan button, and no contact details. | 14, 15 | Later |

## Out of Scope

These are handled outside the mobile app, but the app relies on some of them.

| Item | Why it is out of scope | Notes |
| ---- | ---------------------- | ----- |
| #19 Promo period reset | Resetting the promo period belongs to the admin panel, which is a different development. | The app only reflects the current period and data it receives. |
| #21 Admin dashboard | Separate web app project for authorized Tourism Office personnel. | Manages partner establishment information, visit statistics, promo periods, reward availability and participant limits, and notifications related to reward availability and promotional updates. The app reads this data. |
| Officer verification tool | Separate tool. | Lets tourism office officers scan and verify the single-use claim QR codes generated by Reward Redemption (#11). |
